# 사주랩 성장 실행 계획 (2026-11-02, 리서치 100곳 기반)

리서치 보고서: claude.ai 아티팩트 "사주랩·도장찍기전에 성장 리서치"(사장님 계정). 이 문서는 실행 상태와 남은 단계만 적는다.
저장소가 공개라 계좌·토큰·개인 연락처는 적지 않는다.

## 웹 현황 (최근 30일, AnalyticsEvent 기준)
| 단계 | 수 |
|---|---|
| 랜딩 방문 | 280 |
| 무료 사주 완료 | 70 |
| 공유 버튼 클릭 | 6 (완료자의 약 9%) |
| 궁합 페이지 방문 → 궁합 완료 | 14 → 2 |
| 결제 시작 → 결제 | 4 → 0 |

공유 카드(`ShareButton`: 카톡·스토리 이미지)와 궁합 초대 링크(`/api/compat-invites`)는 **이미 있다**. 문제는 유입 자체가 적다는 것.

## 1. 결과 공유·궁합 초대 — 이미 있음, 측정만 보강
- 할 일: 토스 v11 출시 뒤 미니앱 결과 화면에도 공유가 있는지 확인(웹에는 있음). 궁합 폼 첫 입력 이벤트를 추가해 "방문 14 → 완료 2" 중 어디서 빠지는지 나눠 본다.

## 2. 띠 궁합 78개 페이지 — 구현 완료(브랜치 `work/tti-compat`)
- `/compatibility/tti`(목록) + `/compatibility/tti/<띠>-<띠>` 78개, 사이트맵·궁합 페이지 링크·FAQ 구조화 데이터 포함.
- 관계는 코드로 계산(육합·삼합·충·형·파·해·원진, 오행 상생·상극). 단정 표현 금지 테스트 포함.
- 판단 시점: 배포 4주 뒤(12월 첫 주) 서치콘솔 노출·클릭. 좋으면 일간 궁합 100개(10×10)로 넓힌다.

## 3. 토스 아침 운세 알림 — v11 승인 후 콘솔에서
앱인토스 자체 자료: 스마트 발송만 써도 MAU 5배, 프로모션과 함께 17배.
1. v11 승인 → 3,894원 실결제·환불 확인 → 출시(기존 순서 그대로).
2. 콘솔 → 마케팅 → 스마트 발송에서 "오늘의 운세" 아침 발송(오전 7~8시) 설정. 문구 후보(콘솔 글자 수 제한에 맞춰 줄임):
   - "오늘 하루 흐름, 30초면 확인해요. 오늘의 운세 보러 가기"
   - "{이름}님, 오늘은 어떤 기운이 들어올까요? 오늘의 운세가 도착했어요"
   - (12월) "2027년 열두 달 중 내게 좋은 달은? 신년운세 미리보기"
3. 콘솔의 유입 경로별 리텐션으로 알림 효과 비교(알림 전 1주 vs 후 1주).
4. 그다음 프로모션 1만 원 시험(입력 시작 15%·구매 버튼 1%·결제 2건 기준, 기존 결정 그대로).

## 4. 신년운세 12월 시즌
- 업계: 12~2월 이용자 약 +20%, 경쟁 앱은 한시 할인·묶음 상품.
- 토스 상품가는 콘솔 등록값(3,894원) 그대로 출시. 할인은 출시 첫 주 반응을 보고 사장님이 결정(콘솔 가격 변경은 사장님).
- 웹 `/new-year`(브랜치 `work/new-year-v2`)는 웹 결제 검증 전이라 비공개 유지. 공개 시점에 "출시 첫 주 한정가"를 붙일지 그때 결정.
