## 10/23 오후 수정: 50~60대 손님에 맞춘 문구·구조 (사장님 승인)
토스 손님은 50대 이상 77%·여성 65%. 결제를 망설이는 이유는 금액보다 ① 믿음(정기결제·사기 걱정) ② 내용을 미리 못 봄 ③ 무엇을 사는지 모름.
- **안심 문구**(버튼 바로 아래): "토스로 한 번만 결제해요 · 자동 결제 없어요 / 열두 달 풀이 · 하루 약 11원꼴 / 산 풀이는 다시 열어볼 수 있어요".
- **1월 무료 맛보기**: 카드 안에 신년운세 리포트의 **실제 1월 풀이**를 그대로 보여주고(`freeMonth` prop), 2~12월은 잠금 + "특히 좋은 달은 언제일까요?".
  → 결제 전에 1월만 먼저 생성해야 한다. 10/26 신년운세 v2 코드를 보고 방식 결정(① 1월만 짧게 무료 생성 ② 월별 간지 계산 결과로 1월 한 줄만 규칙 문장). AI 원가·남용 방지(기기·생일당 1회) 고려.
- **익숙한 말**: 한 해 이름은 `SENIOR_THEME`(재물이 붙는 해·자리와 명예가 서는 해·귀인이 돕는 해·재주가 빛나는 해·내 힘으로 일어서는 해), 전부 존댓말, 본문 17~18px·제목 26px·버튼 19px, `word-break: keep-all`.

## 10/23 오후 2차 수정: "1월 무료"를 "열두 달 흐름"으로 (사장님 피드백)

- 바꾼 구조: ① 내년 한 해 이름 ② **열두 달 흐름 막대그래프**(그 사람 안의 상대 높이, ★ 가장 좋은 두 달) + "흐름이 가장 좋은 달은 1월 · 10월이에요"(무료) ③ 가장 좋은 달의 제목("10월 · 재물이 들어오는 달")만 보이고 **좋은 날짜·재물·가족·할 일은 흐리게 잠금** ④ 버튼 A "열두 달 풀이 열기" / B "좋은 날짜 확인하기" ⑤ 안심 문구.
- 계산: `src/lib/saju/monthPreview.ts`(AI 없음) — 달 기운 = 월간 십성, 좋은 날 = 일간 재성·관성·인성 + 일지 충 없음, 점수 = 기운 점수 ± 충/육합 + 그달 좋은 날 수. 테스트 `monthPreview.test.ts`.
- **유료 신년운세가 지켜야 할 것**: 달마다 그 달 이름·좋은 날짜(이 계산)·재물·가족·할 일을 반드시 보여줄 것 — 미리보기가 약속한 항목. 10/26 신년운세 v2 프롬프트·화면에 이 계산값을 넣는다.

## 10/26 노트북 구현 현황 (브랜치 `toss-v11`, worktree `C:\saju-app-toss`)

| 영역 | 내용 |
|---|---|
| 결과 화면 맨 위 카드 | 한 해 이름 → 흐름이 가장 좋은 달 + **그 달의 진짜 좋은 날 하루를 무료 공개**(나머지 날짜는 잠금) + 그날 할 일 한 줄 → 열두 달 그래프 → 받는 것을 숫자로("내게 좋은 날 N일") → 버튼 → 안심 문구. 흐리게 가린 가짜 글자는 쓰지 않는다 |
| 오늘의 운세(재방문) | 작은 카드 `NewYearMini` — 매일 여는 사람에게 내년 한 해 이름·좋은 달 노출 |
| 구매 후 화면 `NewYearScreen` | 달별 카드 12개(좋은 날짜+요일·재물·가족·할 일)를 **기기에서 바로 계산해 즉시 표시**, AI 총평은 도착하는 대로 아래에 채움(읽는 도중 화면이 밀리지 않게). 실패해도 달별 풀이는 그대로, "다시 불러오기" |
| 결제 `iap.ts` | 상품별(`manual`/`newYear`) 저장·미결 복구. 사용설명서의 결제 콜백 방식(주문번호 저장 후 즉시 true)은 그대로 |
| 서버 | `resolveTossProduct`(sku→상품), report API의 `section=newYear`, 프롬프트 v3(겁주기·건강 금지, 달 제목·좋은 날짜·한 해 이름을 계산값으로 전달해 미리보기와 같은 이름·날짜) |
| 좋은 날 고르기 | 예전 "가장 이른 날"은 무료 날짜의 56%가 1일이라 가짜처럼 보였음 → 구간별 최고점(재물>신용>귀인+일지 육합 가산)으로 변경, 무료 날짜는 세 날짜 중 최고점 하루 |
| 문구 다양성 | 같은 기운의 달이 반복되면 같은 문장이 나오던 것 → 기운마다 3가지 표현을 돌려 씀(한 해 재물 문장 8가지 이상, 연달아 같은 문장 없음) |

이벤트(토스 콘솔 분석): `ny_teaser_view`(year·group·variant·best·purchased), `ny_open_click`, `ny_purchase`, `ny_mini_view`, `ny_mini_click`, `ny_screen_view`, `ny_text_ready`, `ny_share_click`. 버튼 문구 A/B는 사람마다 한 번 무작위로 정해 기기에 저장(`sajulab:ny:variant:v1`). 목표: 결과 본 사람 대비 구매 클릭 1%↑.

### 출시 전 순서 (이 순서를 바꾸면 "결제는 됐는데 풀이가 안 열리는" 사고가 난다)
1. **서버 먼저**: 이 브랜치의 서버 변경(`src/lib/toss/iap.ts`, `api/toss/iap/*`, `src/lib/ai/interpretSaju.ts`, `src/lib/saju/*` 등)을 main에 병합·배포. Vercel 환경변수 `TOSS_IAP_SKU_NEWYEAR`(SKU는 OPS_NOTES 10/23 항목) 설정. 금액은 기본 3,894원(`TOSS_IAP_PRICE_NEWYEAR`로 변경 가능).
2. 서버 배포 확인: 기존 사용설명서 결제가 그대로 되는지(grant가 옛 SKU를 여전히 받는지)를 먼저 본다. 새 SKU가 서버에 없으면 신년운세 grant는 400("알 수 없는 상품").
3. **미니앱 빌드**: `toss-mini/.env.production`(git 제외)에 `VITE_IAP_SKU_NEWYEAR` 추가, 기존 광고 ID·푸시 템플릿·`VITE_IAP_SKU`는 유지. `npx vite build` → `npx ait build`. 이 값이 없으면 신년운세 카드는 나오지 않는다(안전 장치).
4. 콘솔: 새 버전 등록 → **폰 QR 테스트(실결제 3,894원, iOS·Android 각 1회, 환불 필요)** → 검토 요청 → 승인 → 인앱 상품 '노출 켜기' → 출시. 문제 시 콘솔 "롤백하기".
5. 프로모션 재개는 출시 후 1만 원 1차 시험.
