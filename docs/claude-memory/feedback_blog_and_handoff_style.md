**파일을 넘길 때:** 전체 경로를 먼저 적고 `reveal_path`로 탐색기에서 열어 준다. 칸에 넣을 값은 칸마다 코드블록 하나씩, 한 단계씩 안내한다(11/11 "이미지가 어디있는지 알려줘야지", "하나씩 진행하자", "입력칸에 뭘 넣어야하는지 리스트로").

**블로그 글(사주랩 운세연구소, 기존 네이버 계정 blog.naver.com/<블로그 아이디>):** 키워드 나열·"쉽게 풀어 드리는" 같은 AI 말투·가운뎃점(·) 남발 금지 — 운영자 1인칭, 실제 사실(창원에서 사주랩을 만드는 사람, 손님이 묻는 질문, 원칙)로 쓴다. 지어낸 경력 금지. 네이버는 본문 가운데 정렬로 올리니 초안은 처음부터 짧은 줄로. 글 끝에 AI 도움·사람 검수 표기. 하루 1~2편. **태그는 한 줄에 이어 쓰지 말고 한 줄에 하나씩**(`[태그] 하나씩 따로 넣기` 아래 `  #태그`), 안내할 때도 태그마다 코드블록 하나씩. 본문 사이트 링크 끝엔 `?from=blog`(11/13부터, 블로그 효과 측정)(11/13 "메모장에 태그가 하나로 이어져 보이거든").

**초안 폴더 규칙(파일 이름·★바로복사·올릴_순서 부분은 11/18 '폴더에는 완성본만'으로 바뀜. 11/13 사장님 "앞으로 2번 경로(GitHub)로 진행")**: 기본 위치는 **`C:\saju-app\docs\blog-backup\<YYYY-MM-DD>\`** (`<날짜>_<글 제목>.txt` + 같은 이름 `_이미지` 폴더(사진 4장·data.json) + `<날짜>_올릴_순서.txt`). 도구는 `docs\blog-backup\00_도구`(fetch_2027.py·make_blog_images.py·queue.json·README.txt). **만들기·[올림] 표시·queue 갱신은 worktree(`C:\saju-app-y2027` 등, origin/main 기준 새 브랜치)에서 하고 main에 푸시**(docs만이라 Vercel 빌드 없음), 그다음 `git -C C:\saju-app pull --ff-only origin main`으로 사장님 폴더에 바로 보이게 한다. `C:\saju-app`에서 직접 파일을 고치지 말 것(자동화 공유 체크아웃). 사장님에게 줄 때는 `C:\saju-app\docs\blog-backup\<날짜>` 경로 + reveal_path. OneDrive `클로드코드1\사주랩_블로그_초안`은 11/13까지의 옛 위치(더는 갱신 안 함), `C:\saju-reports\blog`도 옛것. 공개 저장소라 초안에 개인 아이디·연락처를 넣지 않는다(본문엔 사이트 주소만).

**달 기준 안내(11/14 첫 댓글 "음력으로 안 좋은 달 치냐")**: 사이트·초안의 '몇 월'은 음력이 아니라 **절기 기준 달을 양력 달 이름으로 부른 것**(year2027.ts: 2월=寅월, 입춘 2/4부터; 절기 달은 양력 매달 4~8일 무렵 바뀜). 다음 초안부터 '좋은 달과 조심할 달' 아래에 이 한 줄을 넣는다.

**제목·연결 규칙(11/16, 조회수 근거)**: 총정리 글 약 2,700회 vs 띠별 글 100회 미만, 결제 3건 모두 총정리→/2027 목록→나이 페이지. 그래서 ① 띠별 글 제목에 대표 나이 3개를 넣는다(예: `2027년 돼지띠 운세, 59년생 71년생 83년생 …`, 양 55·67·79, 말 66·78·90, 토끼 63·75·87, 돼지 59·71·83, 소 61·73·85, 쥐 60·72·84, 개 58·70·82, 호랑이 62·74·86, 용 64·76·88, 뱀 65·77·89, 원숭이 56·68·80, 닭 57·69·81) ② **이미 올린 글은 고치지 않는다(11/16 사장님 "앞으로 변경된 상태로 진행", 수정이 노출에 줄 영향 우려·공식 근거는 없으나 돈 버는 총정리 글 보호). 제목에 나이 넣기·링크 연결은 새 글부터 적용, 새 글 본문 끝 [함께 보면 좋은 글]에 총정리 글들 링크. 블로그 주소는 공개 저장소에 넣지 않고 `C:\saju-app\docslog-backup\사주랩 블로그 글 주소.txt`(11/17 사장님이 바탕화면에서 직접 옮김, gitignore 로컬 전용, RSS로 갱신, 없으면 fill_links가 바탕화면 블로그 .url로 새로 만듦 — 바탕화면에 다시 만들지 말 것)에서 복사하게 안내** ③ 총정리형 글(연대별·월별 등)을 늘린다. 글 주소는 공개 RSS `rss.blog.naver.com/<아이디>.xml`을 파이썬으로 읽으면 나온다(네이버 화면은 Claude 브라우저에서 막힘).

**AI 도움 표기 빼기(11/16 사장님 "앞으로 빼")**: 새 블로그 초안 끝에 '※ 사주 계산 결과를 바탕으로 AI의 도움을 받아…' 줄을 넣지 않는다(이전 메모의 'AI 도움 표기' 규칙은 폐기). 이미 올린 글은 고치지 않음.

**주소는 채워서 넘기기(★바로복사 이름은 11/18부터 안 씀 — 아래 '폴더에는 완성본만' 참고. 11/16 사장님 "여기에주소붙여넣기 빼고 메모장에 주소를 넣어놔")**: 초안(공개 저장소)에는 `[[주소:제목 일부]]`만 두고, 초안을 만든 뒤 반드시 `C:\saju-app\docs\blog-backup\<날짜>`에서 `python ..\00_도구\fill_links.py .` 실행 → 같은 폴더 `★바로복사_<이름>.txt`(gitignore, 주소 채움) 생성. 사장님에게는 ★바로복사 파일만 안내. 다른 컴퓨터가 만든 초안도 받은 컴퓨터에서 한 번 실행.

**하루 2편 구성(11/17 사장님 ㄱㄱ)**: 총정리 글 3천 회는 **네이버 홈판** 유입(사장님 확인). 홈판은 모두에게 해당되는 글이 유리 → 하루 2편 = 띠별 1편(검색용, 제목에 나이) + 모두에게 해당되는 글 1편(홈판용, 먼저 발행). 후보: 띠별 궁합(11/18 완료), 이사하기 좋은 달 띠별, 60/70/80년대생 총정리, 입춘·띠 바뀌는 날. **네이버 주제는 모든 글 '주제 선택 안 함'**(11/20 사장님: 조회수 가장 높은 총정리 글이 주제 없음, 네이버 주제 목록에 운세 칸 없음 → 초안 txt 맨 위 `[주제]` 줄로 안내).

**새 글 구조(11/18 사장님 ㄱㄱ, 상위 글 1,531편 조사 근거)**: 본문+표 2,200자 이상, 맨 앞 '한눈에 보는 답', `▶ 소제목` 줄(사장님이 인용구로 넣음), 표 2개는 같은 폴더 `<글 이름>_표.html`(본문엔 `(표 ①)` 자리), 띠별 제목에 출생년도 4개 + '한눈에', 나이별 문단 5~6개, 자주 묻는 질문 3개, 시리즈 문구 + 앞 글 2편 `[[주소:…]]`. 상세는 `docs\blog-backup\00_도구\README.txt`. **정렬 비교 시험(11/18~)**: 띠별 글 = 왼쪽 정렬·문단형, 총정리·홈판 글 = 가운데·짧은 줄 → 1주 뒤(11/25) 순위로 판단해 위 '가운데 정렬 짧은 줄' 규칙을 유지/변경. 띠 12편 다음은 queue의 년생별 글.

**폴더에는 완성본만(11/18 사장님 "올린순서 메모 만들지 말고 파일명에 1순위", "바로복사 파일만 남기자", 인용구·표 붙여넣기 안내는 "설명이 너무 어렵다")**: 날짜 폴더엔 `1순위_<제목>.txt`·`2순위_<제목>.txt`(주소 채운 완성본, 로컬 전용)와 같은 이름 `_이미지` 폴더만. 원본은 `00_도구\원본\<날짜>\`(저장소), fill_links.py가 완성본 생성 + `.git/info/exclude` 등록. `_올릴_순서.txt`·★바로복사 접두어는 더 쓰지 않음. 표는 make_table_images.py로 사진, 소제목은 그냥 한 줄 — 사장님 일은 "글 복사 + 같은 번호 사진 넣기 + 정렬·태그·예약"뿐. [예약] 표시는 queue.json만.
